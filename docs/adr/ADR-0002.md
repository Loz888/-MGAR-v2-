# ADR-0002 · P1 生命周期与恢复边界

Version: lifecycle.v1

本决策细化 P1-03、P1-04、P1-05 已要求的失败传播、取消、租约恢复和 resume 行为，
不增加数据库枚举、不修改已冻结迁移，也不改变终态不可逆、预算原子预留和未知副作用不重播等不变量。
依据为 02.C/E/F/I、07.A/B/C 及 P1-05 的取消/完成/恢复验收；所有分支须由真实 PostgreSQL 测试审查。

| 现有状态 | 操作 / 条件 | 后继 |
|---|---|---|
| queued | 有效编排器 BeginPlanning | planning |
| planning | 已校验计划原子提交 | running |
| running | 当前计划全部必要节点及最新独立 verdict 成功 | verifying |
| verifying | 再次确认必要节点与有效 verdict | succeeded |
| running / verifying | 必要节点失败、取消、永久依赖阻塞或成功证据被撤销 | failed |
| 任意非终态 | 显式用户取消、Revision CAS | cancelled |
| running | 无活动执行槽、仍有待调度任务且总委派预算耗尽 | blocked |
| running / verifying | 未知模型/非幂等副作用，无法安全自动恢复 | interrupted |
| blocked / interrupted | 显式 resume、有效编排器、预算和副作用条件均已满足 | running（已有计划）/ planning（无计划） |
| succeeded / failed / cancelled | 再次提交同一 ID、resume、取消、收尾 | 拒绝，保留 finished_at 与历史 |

运行时取消/失败在同事务冻结 Workflow 终态、取消未终结任务、释放执行并发槽并写事件/Outbox。
未知模型费用与预留保持，不以取消推导外部动作已撤销。非终态不设置 finished_at。
Run 使用 run_id 作为统一 trace 关联 ID；Trace 不代替权威事件。

CLI 提交在同一事务创建 Run、预算及初始编排器租约，防止恢复扫描在初始计划提交前抢占。
计划提交仍为独立持久 checkpoint；若提交进程在计划提交前死亡，Run 可恢复到 planning，
但恢复扫描不会猜测或生成计划，须由受信控制面提供有效候选计划。
应用或汇总验证结论时先锁 Artifact，再在新的 SQL statement 中读取最新 verdict，
使先提交的撤销结论不能因旧快照被忽略；锁等待后的受控提交再次检查租约有效期。

恢复扫描只读取持久状态、应用**已存在的受信验证记录**并重建 ready；不会自动执行模型、工具或 Agent Loop。
没有 verdict 的 output_ready 等待验证，不能被 Worker 的成功声明提升为 succeeded。
verifying 是独立持久 checkpoint，恢复后不重复产生已完成的 Task 或付费调用。

重规划后的旧 Task 终态保留；旧代非终态任务由受控恢复取消，释放 claimed/executing 所占并发槽，
但不退回已经消耗的委派次数、不释放未知调用费用、不删除旧 Artifact 或失败证据。
当前代过期且达到 max_attempts 的任务安全失败，attempts/retry_count 不在恢复扫描中暗中增加。

信任边界：P1 的 Go Store/CLI 属于本机受信控制面；Worker 没有数据库管理员凭据或公开任意写入接口。
完整 HTTP 身份认证、Capability Gateway、真实 Verifier 与 Artifact CAS 均属于后续任务，不能据此声明 P5 安全验收完成。
未知副作用的人工核对/结算流程未实现时，resume 继续拒绝；不通过试探调用来解除阻塞。

P0-01 的文档描述的是当时冻结的设计快照；本 ADR 补充其明确未穷举的生命周期边界。
自动检查与真实故障证据以 `evidence/batches/P1-05/` 为准，限制见 `docs/limitations.md`。
