# ADR-0019 · 角色输出契约与可证实停止的只读失败

Status: APPROVED — 用户明确要求本批修复并安排新冻结实验。

真实首轮34次调用的输出与日志保留在C；本批只使用development任务与本地HTTP调试。
旧dispatch混合Planner和业务回答包装，未给角色完整任务及final Schema；网关即使
得到可信ExecutionStopped也统一把执行后错误记unknown。修复这两项，不改旧记录。

每个角色获得同一版本化决策封套（type/tool_call/final），但只获得适用于本角色的
final Schema和任务。Planner输出Proposal本体，不混入answer；Research/Data/Action
保留真实工具Observation；严格Aggregator保留MergeResult；基线Aggregator/Single
输出公开业务报告格式（answer/refuse、版本、指标、理由和实际引用），不加载Oracle。
描述与Schema不授予能力，Go现有计划/证据/权限Validator仍为权威。

只读调用在Execute已返回错误、错误链有可信ExecutionStopped=true、内外context均未
过期/取消且资源账本已释放时，结算failed并返回不可重试的失败。无停止证明、写操作、
超时、无效结果或资源/结算异常保留unknown。历史unknown不改写，不据此恢复旧轮。

新轮必须独立身份、日志、冻结契约，累计预算计入原轮保守USD0.033850，不增加USD2。
复用原24题时必须标为修复后回归，不能声称新未见holdout，也不调旧题答案或选择性删题。
