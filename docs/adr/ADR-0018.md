# ADR-0018 · 零发送初始化失败与原分配恢复提案

Status: PROPOSED — 当前正式分配不得自动重跑；只读就绪门禁修复不启用恢复。
日期：2026-10-26。范围：P7-06C；拟拆分 P7-06E，不进入 P8。

## 现象和最小复现

P7-06D 在 `be8d780` 通过，C 对账修复在 `801668a` 通过全量回归。
正式执行 `bash scripts/eval.sh --live --confirm-live` 实际退出 1，返回空 Report。
数据库标记 `92d7ff2b-cf3d-5ec3-a1a0-c938f24aa4a7` 已创建，状态 queued；
固定正式 journal 目录未创建，未到 Provider 构造/发送路径，96 项均 NOT_RUN。
日志和只读数据库诊断见 `evidence/batches/P7-06C/`，不将此失败记为真实模型实验。

实际 public schema 只有 001–004，checksum 与源文件一致，缺少 005 的工具/并发
预算字段及 006 的资源准入表。`store.Open` 只连接，不迁移；`CreateRunClaimed`
使用旧字段且先提交，所以成功写入 marker，随后的 `ConfigureBudget` 引用新列失败。
随机测试 schema 自动应用 001–006；其成功没有证明实际 public schema 已升级。
这是运行准备遗漏，不是 API key 或 2 美元额度不足。

## 本轮直接修复

在 `claimExperiment` 的任何 marker 写入前，以只读检查确认所需迁移及其 checksum，
并检查关键预算/资源结构。旧 schema、篡改 checksum 或查询失败均拒绝；不自动迁移。
真实 PG 反例使用自有随机 schema，验证旧 schema 不再留下 marker。
此修复不恢复正式 marker，不修改既有迁移，不改变预算或允许未知请求重播。

既有迁移 005/006 随后已用受保护的 `go run ./cmd/mgarmigrate` 补应用，退出 0；
原 marker 未恢复或重跑。升级前/后只读诊断分别保存，恢复例外仍待审阅。

## 已有规则与冲突

P7-06B 的一次性协议明确规定：任一步失败即保留 marker，不自动 force/resume/reset，
即使发生在第一条 HTTP 前。新建身份、删除 marker 或直接重跑都会破坏该协议。
当前没有产生模型调用，因此无需扩大预算；但“零发送初始化恢复”是现有设计没有
允许的例外，必须先审阅并授权，而不能仅凭总额仍为 2 美元猜测放宽。
仓库 [工作协议](../../03_CODEX_WORK_PROTOCOL.md) 要求：
“需求与协议冲突：先写 ... ADR ... 卡状态 BLOCKED，等待用户批准。”

## 建议方案：P7-06E，严格限定零发送初始化恢复

1. 重新确认本轮已补应用的既有 005、006，以及 001–006 checksum 和新结构；
   无新 DDL 文件，无生产库操作。
2. 保留原 marker、96 个 UUID、模型、题目与每份 20833 微美元，整轮最多 USD 2。
   只允许接管本次 queued/revision=0、计划摘要匹配的初始化 marker；通过既有
   Orchestrator lease/epoch CAS 防止两个恢复进程同时取得权限，不删除或重建 marker。
3. 恢复前再次核对：正式 journal 不存在；原分配的全部 UUID 在保留的控制/实验
   namespace 内没有任务、模型或工具调用；原 marker 的预算零使用、零预留，
   没有 unknown/pending，且没有任何已发送请求证据。任何不符立即停止。
4. 在原 marker 上完成零消费预算初始化并终态化，然后独占创建原 journal，
   执行同一份原 96 项计划。不得复用其他历史分配、转移余额或调整 prompt/holdout。
5. 先用本地 HTTP、真实 PG、两个独立 OS 进程验收；零发送恢复与正式执行分别留证。
   已产生生成请求、任何未知账目、journal 缺失但历史有调用的情况均不可自动恢复。
   此次恢复若再次结果不明，保留现场并停止，不形成通用循环重试开关。

替代方案是继续封存当前分配；不能为了启动而另造 UUID 或增加费用。
E 通过后再回到已授权 C，完成真实执行与独立评价；目前没有实施 E 恢复代码。

## 风险与影响测试

主要风险是把遗失 journal 误当成零发送，或两个进程重复取得同一分配。要求同时检查
PG 证据、固定身份、冻结摘要、CAS/文件现场及 lease/epoch，任何缺口拒绝。
验收至少覆盖缺迁移、checksum 错、非零预算、隐藏调用、未知调用、已有 journal、
错状态/计划/UUID、双进程竞争及接管后崩溃。原未知调用不重试测试必须继续通过。
