# ADR-0014 · P7-03 无内部验证基线与严格依赖门禁的冲突

状态：**提议，待批准；没有改变运行协议**。

## 已确认事实

- `05_EVALUATION_PROTOCOL.md` §3 的 B1/B2/B3/A2 关闭内部 Verifier，保留最终外部 Oracle。
- `02_ARCHITECTURE_CONTRACTS.md` §E 要求所有直接前驱完成且产物满足验证条件才可 ready；
  §C 要求独立 verdict 后任务成功。`01_PROJECT_CHARTER.md` I8 禁止将未验证产物标记为已验证成功。
- `internal/store/tasks.go`、`lifecycle.go`、`task_inputs.go` 实际执行这些要求。
  `MergeContext` 只消费固定且已验证的直接输入；当前没有候选证据与语义通过的双层结果状态。
- P7-02 的完整链路在这些门禁下已通过。其独立重执行还拥有自己的 verify Claim、工具预算和资源许可。

## 最小真实复现

`tests/integration/eval_boundary_test.go` 使用真实 PostgreSQL 与 CAS，只调用正式 API：
创建 source→sink 计划、Claim/BuildSnapshot/StartTask/PublishArtifact source，
不提交任何 verdict，再 ApplyVerdicts/RefreshReady/Claim sink/FinalizeWorkflow。

结果：`source=output_ready, sink=pending, claim=NO_READY_TASK, workflow=running, verdict_count=0`。
命令与真实日志见 `evidence/batches/P7-03/conflict-reproduction.log`。
该测试通过只证明严格门禁生效，**不证明 P7-03 的 runner 或基线通过**。

## 为什么不能静默“适配”

关闭重执行但用候选内容自身的 hash 自动签发通过 verdict，然后继续把汇总事实标为
verified，会混淆内容完整性与业务正确性，违反 I8 并改变消融含义。
把 B1/B2/B3/A2 也全部做独立语义重执行，则实际没有实现规定的 treatment。
删除依赖门禁、直接写任务 succeeded，或将候选误报成真实 Workflow 成功同样不可接受。

## 建议方案 A：隔离的基线实验执行层（推荐，待批准）

1. 严格 MGAR Runtime 保持现有语义；B4/A1 使用其完整验证链路。
2. 为 B0/B1/B2/B3/A2 建立显式实验适配层。只允许使用同版本的合成 Tool、
   同一个模型适配、预算/身份/资源准入；无模型授权扩权、无原始 SQL/shell/生产写入。
3. 中间交接使用单独的 `candidate_evidence` 实验信封：原始内容、SHA、Run/Task/
   Plan 来源与工具版本固定，明确 `semantic_status=unverified`。不签发伪造 passed verdict，
   不调用严格 Runtime 的已验证依赖解锁接口来承载这种语义。
4. 实验完成与生产 Workflow succeeded 分别命名。七组主要比较口径均为冻结外部
   Oracle 的 `oracle_pass/all_assigned`，保持所有失败、超时和预算耗尽。
   严格 Runtime 的 Workflow 成功诊断在独立基线组记 N/A，不能当作其失败率或给 B4 加分。
5. 所有组记录相同上限和实际调用/耗时；隔离层新增管理开销计入实际耗费，公开工具清单、
   执行拓扑和差异。候选交接接口需独立做越权、哈希/版本变更和预算负例。
6. 在开始正式 60×7 实验前先验收此边界；不能靠一份配置文件假装已存在七种执行路径。

该方案是实验方法和执行语义的明确补充，**不视为原规格已自动批准**。
建议先拆出 P7-03A 边界/适配验收，再做 P7-03B 公平 runner；各子批控制生产文件和协议数量。
具体接口契约在 P7-03A 编码前冻结，若需要 DDL 再单独提出，不预先授权迁移。

## 方案 B：在核心协议中区分完整性通过与语义通过

新增受信实验策略与分层 verdict，并调整 Ready/Context/Merge/终态/统计契约，
保证任何未语义验证内容都不被显示为 verified。此方案改动核心协议，可能需要
追加迁移和多张独立任务，不属于本次可静默实施的小型辅助模块。

## 当前决定与门禁

P7-03 标记 BLOCKED；P7-04/P7-05 不前进，不进行付费模型调用。
提交 CHANGE_REQUEST 后等待用户选择/批准；生产行为及 P7-01/P7-02 的验收结果保持不变。
