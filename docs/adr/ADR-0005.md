# ADR-0005 · 有界重规划与活动实例撤销

Status: ACCEPTED within user-authorized P4-02 implementation

细化 02.D/F、07.A/B/C；不修改状态机、不增加 DDL。复用 ADR-0004 的增量计划检查，
模型只提交 `replan.v1` 候选图；失败节点和类别须与当前计划中的失败状态或最新否定 verdict 对应。
安全失败、未知模型调用和非幂等副作用不进入自动重规划。调用本接口需要受信 Orchestrator Claim。

MaxReplans（至多 8）、深度（至多 6）及整数微美元成本策略由可信调用方提供，第一次尝试写入
不可变 workflow_events，后续不得放宽或替换。每次尝试在 Workflow 锁内计数；格式错误也占次数。
候选重算节点数乘可信单节点上界必须不超过策略总上界，还须有足够剩余委派预算。
这里的上界是准入策略估算，不是 Provider 实收或 P6 的全局调用预留；没有发起付费调用。
已接受方案忽略 base/rationale/节点边顺序进行语义去重；非法原文按摘要记录，改写非法原文仍受次数上限。
重复方案或拒绝次数耗尽进入 failed；达到接受次数上限后的下一次请求被拒并收尾，不再激活计划。

已有模型 unknown/reserved 或活动非幂等工具结果使 Replan 返回 UNSAFE_REPLAY，不取消或重发。
其他活动任务可在同一事务中 cancelled 并释放并发预留，再分配新计划任务；已完成历史不可修改。
旧 Worker 受 active plan/epoch/revision 检查拒绝写入。新计划 CAS、取消、差异、尝试与 Outbox
同事务提交；任何数据库失败整体回滚。旧 Plan/Artifact/verdict 和失败依据保留，删除节点显式列入 Diff。

此处提供确定性控制 API，候选由调用方交给它；不增加自动付费 Planner 或自动重试循环。
真实跨进程 CAS、活动 Worker fencing、非法图、次数/深度/成本/委派预算和事务回滚都有回归。
