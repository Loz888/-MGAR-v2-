# ADR-0003 · 本地 CAS 发布与跨存储失败边界

Status: ACCEPTED within P3-01 authorized implementation

本决定细化既有 02.H，不改变状态机或授权协议，不是规格冲突。
内容存储使用 Linux 私有 0700 目录、0600 普通单链接文件、SHA-256 文件名和根目录约束。
写入上限 1 MiB，经 temp/write/fsync/同文件系统 rename/目录 fsync 发布。
同进程互斥与跨进程目录 flock 保护同名发布；已存在对象必须重读、校验哈希、大小并比较字节，
不覆盖损坏对象，不声称 SHA-256 碰撞在数学上不可能。

数据库与文件系统之间没有共同事务。先预检查当前 Claim，再在数据库事务之外写内容，
最后重新检查 Run/Plan/Role/Owner/Epoch/Revision/数据库租约并在短事务中写不可变元数据、
output_ready、运行槽计数、事件及 Outbox。内容本身不会获得验证通过状态。
文件写后数据库失败或提交结果未知时，允许留下孤立内容；不得因错误返回就删除它，
否则可能破坏另一 Producer 或已提交但响应丢失的引用。

Inventory 提供物理对象哈希清单，供受信运维与全部数据库引用比对；本阶段没有自动删除 GC。
进程崩溃可能残留 `.tmp-*`，通过 StagingInventory 单独盘点，保留到不存在活动写者且完成引用核对后处理。
不承诺跨数据库和文件系统原子提交、宿主断电或磁盘故障恢复。

ACL 以同 Run、Producer Task 和角色/计划绑定为基础；消费授权和固定输入在 P3-02 实现。
本机 Go Store 是受信控制面，不能向模型开放数据库或任意 CAS 文件路径。
P5 的 Capability Gateway 负责非受信远程调用方身份，CAS 私有目录不是代码执行沙箱。

验证涵盖真实多进程共享 CAS 与 PostgreSQL、同内容不同 Producer、Outbox 故障回滚后孤立对象、
过期租约与旧 Revision 拒绝、篡改/路径/软硬链接/大小限制。
