# ADR-0008 · P6 分类资源准入

状态：P6-02 实施决策，落实卡片要求的单机多进程权威准入。

追加迁移 006：resource_pools 保存 llm/cpu/db 的全局 capacity/queue_limit；
resource_requests 保存有界排队票据、任务/owner/epoch/plan 绑定、token_hash、
priority、deadline、状态和 revision。所有新写路径都追加现有 Workflow event
及 outbox。配置也由持有相关 Run 控制权的可信控制面写入并在该 Run 审计；
不存在 Worker 自行配置或直接访问数据库的接口。

锁顺序保持 Workflow → Orchestrator(若需要) → Budget → Task → Pool → Ticket
→ outbox。全局队列选择只读取其他 Run 的可用性，不在持有 Pool 时反向锁
其他 Workflow。数据库 Pool 行锁是跨进程权威；本地 semaphore 是附加限制。

queued → held → released；queued 可 cancelled/expired；held 停止未确认时转
unknown，仍占容量。返回真实完成/取消确认后才释放 held/unknown。绝不仅因
时间过去就重新分配可能仍在执行的许可。正常队列超时取消、执行器响应取消
并确认退出不会泄漏；进程崩溃或未确认清理保守保留，需控制端证明停止。

排队按 priority + floor(等待秒数*10)、created_at、UUID 排序；priority 0..10，
排队上限、总请求期限均有硬界。最长等待保证有条件：无 unknown 占位且执行
器在规定时间内停止；否则请求到期明确失败，不宣称无限等待最终必成功。

Gateway 默认将 Action/Verify 工具分到 CPU，其他受限读取分到 DB；模型
适配使用 LLM 池。未知代码仍只能通过 P5 沙箱。迁移、新准入/释放/审计、
跨两个 OS 进程最后许可竞争、排队取消/老化、执行取消必须真实验证。
