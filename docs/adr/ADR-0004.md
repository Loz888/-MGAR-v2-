# ADR-0004 · 增量计划的来源校验与显式复用

Status: ACCEPTED within P3-04 authorized implementation

本决定细化 02.D/H 和 07.C 的复用协议，不引入新的任务状态或自动重规划策略。
已完成 Task、原 Artifact bytes 与来源版本不可修改；新计划对合法旧结果显式写 reuse_artifact_id，
其 task_instance_id 指向原来的终态任务。需要重算的节点分配新 Task ID，递归影响后继。

复用须同时匹配节点需求、父边集合、模型配置、工具策略、输出工具版本、全部输入 ID/hash/
Producer/来源版本，以及最新有效 verdict 和实际 CAS 字节。仅同内容哈希不足以复用。
输入配置由追加迁移 004 的 plan_node_configs 固定；配置表和计划映射均不可更新或删除。
旧计划没有该表记录时，合法来源仍须从真实发布的不可变 ContextSnapshot 和 Artifact 元数据恢复，
缺少实际 CAS/快照来源的 P1 合成元数据默认重算。
执行配置从数据库中 Task 与当前计划节点的关联解析，不用调用方自报的 NodeKey 定位授权记录。

受信 ProposeIncremental 按现有锁顺序锁 Workflow、Orchestrator、预算、Task、Artifact，
在 Artifact 锁后读取最新 verdict，计算差异并原子提交映射、配置、计划 CAS 与 plan_committed Outbox。
相同 base_version 的多进程竞争只能有一个提交者。暂拒绝仍有 claimed/executing/output_ready/verifying
实例的 Run，不暗中覆盖正在运行的工作；活动执行接管和动态重规划仍由 P4 负责。

Ready、Claim 和收尾只在存在显式复用映射时接受早期 source_plan_version，
并继续检查来源和最新 verdict；快照仍记录原始来源版本，不把它伪装成新版本。
复用后撤销 verdict 会阻止当前计划成功，但不会改写历史 Task 的 succeeded。
委派预算不重置、不退回，复用本身不产生新 Claim。

验证包含真实 CAS/PG 的 A/B→C 增量重建、B 复用、历史逐字比较、固定新输入、预算守恒、
版本/配置/撤销拒绝、拒绝补丁后旧 bytes 不变、Outbox 故障回滚及真实独立进程 Plan CAS。
