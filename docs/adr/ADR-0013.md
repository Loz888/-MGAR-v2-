# ADR-0013 · P7-02 合成业务运行适配

状态：实施；范围仅 P7-02，不新增 DDL 或改变持久化协议。

现有组件已有独立验收，但尚无完整业务启动入口。新增薄运行适配，复用
Plan/Claim/Snapshot/Gateway/资源账本/Outbox/Verifier；Python 仅获得任务 Token，
不获得数据库、Docker 或模型凭据。付费 Provider 不在入口允许值内。

Planner 的 Mock 决策先在只读 research 身份的 bootstrap 任务下完成，模型调用
同样先预留账本。候选计划经 Go 解析、校验后提交第二版；bootstrap 成功历史保留。
程序化 Verifier 在独立 verify 任务下持有执行 Claim，重执行也先写工具账本并取得
DB/CPU 资源许可；不复用已进入 output_ready 的生产者 Claim。Verify receipt 完成后
才解锁汇总，避免独立检查成为未记账通道。
Research/Data 独立 Python 进程并行，Action 只写本次私有临时复制工作树并在
现有无网络 Docker 沙箱测试；只读分析计划不创建 Action。

SQL/test Artifact 仍为现有 Observation 结构，独立 Verifier 重执行原始观测。
业务汇总适配只把已验证且授权的直接输入映射为有类型的标量事实，再调用现有
handoff.Merge；引用保留原 Artifact、哈希、来源任务和计划版本。不得将模型的
verified 字段作为授权。最终报告必须与可信输入的确定性汇总一致。

默认 Mock 的决策使用真实工具观察，不读取 oracle 答案文件；外部冻结 Oracle
在 E2E 测试中独立判定。Mock 字节估算 token 明确标记 local_stub，非供应商账单。
失败、未知和缺证据不进入 succeeded。运行后导出审计、原始 Artifact 与验证结果，
仅清理本次拥有的 schema/reader/临时文件；根 fixture 的哈希必须不变。

验收：两个业务正例、每个角色伪造证据、缺证据/策略拒绝、原目录不变、真实
数据库权限、模型/工具前置账本、独立进程并行及最终引用验证。
