# ADR-0001 · 独立执行边界和事务锁顺序

Version: adr.v1
Implementation: DESIGN_ONLY
DefaultAdapter: LocalSandboxAdapter

日期：2026-10-22。状态：P0-01 固化现有规格；未实现、未做运行时验证。
依据：[01.5](../../01_PROJECT_CHARTER.md)、[02.F/J](../../02_ARCHITECTURE_CONTRACTS.md)、
[07.A](../../07_IMPLEMENTATION_PLAYBOOK.md)。本 ADR 没有改变这些规范的行为。

## 背景与决策

MGAR v2 的重点是跨 Agent 编排与证据链，应在当前独立仓库中单独运行和验收。
不复制原 Coding Runtime；不修改 durable-coding-agent-runtime-source 仓库，不借用其测试成绩。
新项目只实现编排必需的最小 ExecutionAdapter 边界，不重做 Patch Engine 或 Agent 历史循环。

| 选项 | 收益 | 代价 / 风险 | 结论 |
|---|---|---|---|
| LocalSandboxAdapter | 默认可独立复现；合成任务、工具和无凭据沙箱的权限域易控制。 | 仍须实现并验证真实隔离、资源上限、故障窗口；不能只凭目录限制称安全沙箱。 | 默认路径，当前未实现。 |
| 原 Runtime 适配器 | 通过受控进程/HTTP 接口复用已有单任务执行能力。 | 增加服务、接口版本、权限和故障依赖；不能把旧 Runtime 的成功当成 MGAR 协作成功。 | 可选集成，不是默认启动依赖。 |
| 复制旧 Runtime 源码 | 暂时减少外部调用。 | 重复维护执行、Patch 与恢复系统，稀释本项目边界。 | 拒绝。 |

适配器仅接受经 Go 控制面授权、固定版本/输入快照/工具域/预算的执行请求，返回产物和证据引用。
具体序列化字段和方法签名由对应后续任务定义，本卡不创造新持久化协议。
编排所有权、计划 CAS、预算与结果提交留在 Go 可信控制面；替换适配器不能绕过这些守卫。

## 冻结的行锁顺序

```text
workflow_runs → orchestrator_leases → run_budgets → task_instances → outbox_events
```

先锁 Workflow；需要编排器所有权时在此之后验证/锁其 Lease，再锁 Budget、Task，最后写通知。
路径不涉及某类行时可跳过，但不得倒序；多个 Task 按稳定 task_id 顺序。
这是对 02.F 示例和 07.A 的细化：不能先锁 Task 再反向争抢 Workflow/Budget。
追加 Plan、Inbox、审批和 verdict 的具体冲突处理仍由对应实现卡规定；不能据本表编造其 DDL 或运行时行为。
所有数据库事务只进行授权、状态、预算、event/outbox 写入；LLM、远程 API 和测试在事务外。

## 后果、风险和验证

单机 Linux/WSL2 是设计边界，不承诺跨主机容错，不承诺外部 exactly-once。
Artifact 文件与 DB 没有跨资源原子提交；需 orphan inventory 和受控 GC，不能抹去崩溃窗口。
Mock 不等于真实 Agent；模型未知调用保留费用上界且不默认重试；密钥不进入不可信沙箱。
后续实现须分别验证本地适配器独立运行、旧 Runtime 缺失时默认路径、恶意代码隔离、
旧 owner/revision 拒绝、相反调用场景下真实 PostgreSQL 并发无死锁、未知副作用不重播。
以上运行时测试当前均未运行。

本卡自动检查：默认适配器、两种适配方案的权衡、锁顺序和边界声明是否漂移，
并用临时文档变异证明错误会被拒绝。静态检查无法证明隔离、并发正确性或模型能力。
若后续出现规格冲突，先新增 ADR/CHANGE_REQUEST 并将对应卡标为 BLOCKED，等待批准。
