# ADR-0021 · 聚合短回执与模型失败分类

Status: ACCEPTED FOR DEVELOPMENT — 用户要求开发集复现修复并审阅下一冻结轮；不执行付费轮。

round2的13个聚合末次调用为failed且输出达到1024 token，Worker只记录policy_denied。
原供应商响应文本/finish_reason未保留，不能据此断言全部历史根因。开发桩以前固定报5
输出token并完整返回任意长MergeResult，未约束输出容量。Go模型代理将多种失败统一
转为403，Python据此误报权限错误。

保留1024输出和原工具/Verifier权限。aggregate.merge仍在可信Go端读取固定直接输入、
检查来源并形成完整MergeResult；成功工具只向模型返回merge-receipt.v1及完整结果SHA256。
模型final.output回显该回执。发布前在Go端验证当前Claim和同epoch/owner/plan的成功
工具行、CAS回执及摘要，绑定本次真实计算的完整MergeResult，之后执行既有完整产物
验证。Worker输出仍记录回执，Artifact记录完整结果，不能假装模型序列化了完整证据。
伪造/跨任务/陈旧/未调用/未知工具回执全部拒绝，失败不得提升为成功。
绑定与账本已确认但模型回执无效时，将模型对象保存为rejected-merge-receipt.v1失败证据，
由原Verifier拒绝并按已知failed收尾；拒绝包装与完整MergeResult不同，不能误过哈希检查。
绑定或账本仍不明确时不发布完整聚合产物，继续保守中止。

模型错误使用闭合model-error.v1信封。明确区分policy_denied、budget_exhausted、
resource_exhausted、model_input_limit、model_output_limit、model_invalid_response和
model_usage_unknown；状态/用量语义有固定映射且retryable=false。已知供应商用量先
按现有账本结算，即使输出无效；未知或结算不明仍保留上界。错误不包含供应商原文、
请求内容或凭据，不能用错误字段改变账本或授权。Python拒绝不合法/不匹配信封。

历史实验以原源码/报价指纹和日志评价，不能用新文件重写旧冻结配置。旧指纹测试使用
固定历史数据快照；新源码只属于新版本。开发集使用本地HTTP/真实PG/独立Python进程，
容量证明须标明词表下界或字节上界的适用范围，不冒充真实模型质量。
