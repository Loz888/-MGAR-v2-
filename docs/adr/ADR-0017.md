# ADR-0017 · Flash-1017 官方接口映射与输入预留上界

Status: PARTIALLY IMPLEMENTED / INPUT-BOUND CHANGE PROPOSED
日期：2026-10-26（Asia/Shanghai）。范围：P7-06C；不进入 P8。

## 已核实事实

当前运行环境已注入 `DEEPSEEK_API_KEY`。可信只读请求
`GET https://api.deepseek.com/models` 返回 200，模型列表包含 `deepseek-flash`、
`deepseek-v4-pro`。密钥没有进入日志或 Git。环境状态服务仍将绑定/网络标为 unknown，
因此这里只声称实际 HTTPS 操作成功，不声称平台的全部就绪状态已验证。

官方[价格页](https://api-docs.deepseek.com/quick_start/pricing/)和
[1017 发布说明](https://api-docs.deepseek.com/news/news261017/)确认：
`deepseek-flash` 当前由 DeepSeek-V4.1-Flash-1017 提供。
该别名可能移动，不能声称锁定不可变权重。用户授权版本仍记作 `flash-1017`；
账本/快照/分配 UUID 保留原逻辑身份，序列化请求使用官方 API 名称。
这属于已批准模型的接口映射，不是另选模型。

官方 API 默认启用 thinking，温度在该模式不生效。本批明确发送
`thinking.type=disabled`、`temperature=0`、原定 `max_tokens=1024`，四组一致。
本地 HTTP + 真 PG 已验证请求契约、持久预留先于发送、失败不重试、unknown 不释放。

官方报价为每百万 token：输入 cache-miss 最高 USD 0.30，输出最高 USD 1.20。
离峰与 cache-hit 更低；为跨时间/缓存状态保守计价，冻结最高费率。估算不是发票。
上下文标为 1M；API 文档以 `384K=393216` 定义二进制 K，本批保守采用
1,048,576 token。即使只用十进制 1,000,000，下面的拒绝结论也成立。
公开资料、HTTP 状态、hash 与报价版本见
`eval/live/official-evidence.json`、`evidence/batches/P7-06C/official-check-20261026/`。

## 预算/契约冲突的实际复现

A/B 的已验收策略按**整个官方上下文容量**预留输入，并另预留 1,024 输出 token。
每次预留：

```text
input ceiling = 1,048,576
output bound = 1,024
tokens reserved = 1,049,600 > frozen per-Run 65,536
cost_micros = ceil((1,048,576 * 300,000 + 1,024 * 1,200,000) / 1,000,000)
            = 315,802 > frozen per-assignment 20,833
```

按十进制 1M 也需 301,229 微美元。以上是保守预留，不能据此推算真实请求费用。
当前正式 preflight 退出 2，唯一配置 blocker 为
`conservative_call_bound_exceeds_slot_budget`；未打开正式实验分配，未发生成请求。
将 ContextTokens 猜写为 4096、按 byte/4 收窄、只提高预算、另发一笔脱离分配的
smoke 请求，都不能满足现有约束。提高美元上限也不能解决冻结 token 限额。

## 已实施部分

接口名映射、显式 non-thinking、官方最高费率与公开来源冻结均在本轮授权内完成。
保留 24×4 分配、2 美元总上限、每份额度和 UUID、65536 token、未知保留及严格
Verifier/Ready 语义。没有发送付费请求，没有创建全局 allocation Run 或正式 journal。
原有失败日志、旧缺配置状态与 Mock 证据保留，不改写历史成绩。

## 待批准方案：P7-06D

建议先实施 [P7-06D](../../tasks/P7-06D.md)，以**可证明的实际输入 token 上界**替代
整模型容量预留，再回到 C 的真实执行。这会修改 ADR-0016 的预留策略，需要显式审阅。

1. 获取官方链接的 V4 tokenizer 数据，绑定版本/hash；核实与 Flash-1017 一致。
   官方链接在 `https://cdn.deepseek.com/api-docs/deepseek_v4_tokenizer.zip`，当前只配置了
   API/文档域名；获取前需走支持的网络配置流程。尚未请求该下载，不声称可达。
2. 验证 tokenizer 与实际请求的消息包装/特殊 token/服务端附加内容的关系。
   不能用几个样本 usage 相符代替上界证明，不能无依据加一个常数就宣称安全。
3. 发送前按实际不可变请求计算输入上界，加原有输出上界，交给既有 PG 原子预算
   预留。报价、分配身份与 unknown 上界继续绑定原请求；不转移余额，不重试未知调用。
4. 若无法证明聊天包装的上界，保持 BLOCKED，不以经验平均数启用付费实验。

本提案不增加预算、不减少题数/组数、不改模型、不重用份额、不新增 DDL，也不进入 P8。
输入上界验证单独离线验收后，C 才可启动原 96 项。D 尚未实施或计为 PASS。
