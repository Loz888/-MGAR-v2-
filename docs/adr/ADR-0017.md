## 预算/契约冲突的实际复现

A/B 的已验收策略按**整个官方上下文容量**预留输入，并另预留 1,024 输出 token。
每次预留：

```text
input ceiling = 1,048,576
output bound = 1,024
tokens reserved = 1,049,600 > frozen per-Run 65,536
cost_micros = ceil((1,048,576 * 300,000 + 1,024 * 1,200,000) / 1,000,000)
            = 315,802 > frozen per-assignment 20,833
```

按十进制 1M 也需 301,229 微美元。以上是保守预留，不能据此推算真实请求费用。
当前正式 preflight 退出 2，唯一配置 blocker 为
`conservative_call_bound_exceeds_slot_budget`；未打开正式实验分配，未发生成请求。
将 ContextTokens 猜写为 4096、按 byte/4 收窄、只提高预算、另发一笔脱离分配的
smoke 请求，都不能满足现有约束。提高美元上限也不能解决冻结 token 限额。

1. 获取官方链接的 V4 tokenizer 数据，绑定版本/hash；核实与 Flash-1017 一致。
   官方链接在 `https://cdn.deepseek.com/api-docs/deepseek_v4_tokenizer.zip`，当前只配置了

3. 发送前按实际不可变请求计算输入上界，加原有输出上界，交给既有 PG 原子预算

## P7-06D 实施与上界推导

官方 ZIP 已通过继承平台代理/CA 的 HTTPS GET 下载（200）。完整 archive SHA256 为
`e7310d1dafe0a86d8a5629fe78a7c763760f651db9b8682718a1781dcd6fe495`，
冻结到 `internal/provider/data/deepseek_v4_tokenizer.zip`。仅读取两个 JSON，未执行
ZIP 中要求 `trust_remote_code=True` 的 Python demo。逐文件 hash、源码与完整推导见
`evidence/batches/P7-06D/reference-proof.json`。首次下载失败也保留，不改写为成功。

JSON 的 normalizer 是空 Sequence；前三个预分词步骤只做 Isolated Split，第四个是
不加前导空格的 ByteLevel。验证完整 256 字节字母表都存在于 BPE vocab；BPE 只合并
符号，非空 AddedToken 匹配只会缩短 token 序列；ByteLevel postprocessor 只处理 offsets。
因此，对当前固定 codec，token 数不会超过传入参考串行化字符串的 UTF-8 字节数。
这里没有 byte/4、样本均值或任意安全常数。包内 `model_max_length=16384` 是包装库
元数据，不用于推断当前 API 容量；API 容量仍按官方价格页 1M 单独保存。

计数适用范围严格限制为一条固定 system 文本、一条 user 文本、non-thinking、
非流式生成。按发布的 chat_template 分支，模型输入为：

```text
BOS + fixed_system + User_marker + user_content + Assistant_marker
```

所有 marker 均按完整 UTF-8 字节预留，特殊 token 识别不会扩大计数。仅在该官方
参考串行化契约内启用该证明。额外消息、name、图片、native tools、prefix completion、
thinking 及 response_format 均不纳入此模式；这些特性可能需要不同包装，因此拒绝。
实际请求省略原生 JSON format，仍由同一 system 指令要求严格 JSON，并由控制器
校验真实输出；输出失败仍按已知 usage 结算，不能靠自评提升成功。四组同一模式，
此变更在任何 holdout 模型生成前冻结。

客户端有 48,000 字节 user payload 上限。固定 system+marker 为 454 字节，所以单次
输入最大预留 48,454 token；加 1,024 输出，按最高费率需 15,765 微美元。正式 preflight
已退出 0，未创建正式 allocation。每次发送仍根据**实际不可变请求**计算，先提交原有
PG 预留；报价版本后缀绑定完整证明 fingerprint，输入摘要绑定真正发送的序列化字节。
archive/config/tokenizer/template 的任一 hash、模式或报价绑定不符均在发送前拒绝。

未来若服务端不再遵守该参考串行化/codec 契约，该证明不适用；尤其观察到 usage 超过
绑定上界时，按 unknown 保留原预留并停止后续分配，不能按更小数字结算后继续。
这是受信 API 契约下的保守上界，不承诺不可变权重或供应商发票精度。
