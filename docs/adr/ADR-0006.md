# ADR-0006 · 独立证据校验与授权提交

Status: accepted within P5-01 scope

P0 的 evidence.v1 是尚未运行的设计样本，缺少 07.F 要求的生产者、重放条件和预期观察。
P5-01 将这些字段补成必填，并更新契约索引；没有已部署的 v1 Evidence 消费者被迁移。
不改变实体/状态机、已发布 SQL 迁移或既有 Artifact 身份。历史设计样本可由 Git 查询。

Verifier 不以模型陈述作为期望值。可信控制器提供 Requirement，绑定 kind、tool_version、
具体 Recipe 和 Expected Observation；Evidence 中的自述值必须与之匹配。
文件 SHA 和精确引用由实际 CAS 字节校验，只证明对应的字节属性，不能外推任意自然语言结论。
测试与 SQL 必须有独立 Replayer；尚未配置时返回 unverifiable，不接受 Reviewer yes/no。

提交入口只存在于可信 Go 控制面，持有有效 Orchestrator Claim 才可使用；不向 Agent 暴露
原始存储或任意 verdict 写入接口。Worker 数据库身份不能写 verdict 或 Workflow。
P5-03 将在工具入口上进一步绑定受控凭据及细粒度范围。

校验前短事务授权当前计划的结果、来源关系和固定快照；长时间重执行在事务外；
提交前重新检查计划、租约、元数据、来源与真实字节，防止检查期间输入失效。
Verdict 行、详细 checks 审计事件、Outbox 同事务追加，沿用原有锁顺序。
`evidence_artifact_id` 指向被实际检查的对象；完整判定保存在不可变事件 payload，
不将报告伪装为原 Producer 新产生的 Artifact。`passed=false` 同时阻挡 failed/unverifiable；
两者区别由事件中的 verdict.status 保留，不能据缺少数据宣告成功。

正负例覆盖伪造成功、缺失引用、跨 Run、旧版本、Reviewer 字段注入、并发追加、事务回滚、
检查中 Plan 变更和独立 Worker 登录越权。P5-02 负责重执行，P5-04 负责不可信代码沙箱。
