# ADR-0007 · P6 工作流预算扩展

状态：P6-01 实施决策；落实任务卡已要求的工具次数、并发和价格冻结。

现有 run_budgets 已有模型/Token/美元/任务计数；P5 的工具计数只有每任务
64 次上限。为实现 P6-01 的单 Run 全局准入，在追加迁移 005 中添加
max_tool_calls、reserved_tool_calls、settled_tool_calls、max_call_concurrency。
原实体、主键、现有字段、状态和锁顺序不变，历史迁移不修改。

所有模型/工具预留都先锁同一 run_budgets 行，并条件更新；工具结果与
计数结算及 outbox 共事务。reserved/unknown 都保留次数和并发占用；
成功/已知失败消费一次调用并返还未用 Token/费用上界，不退还已尝试次数。
未知不能变为实际零用量。物理执行并发暂保守按未确认账本计数；分类资源池
属于 P6-02，本卡不实现。迁移从现有 tool_invocations 回填计数，额度至少覆盖
已有记录，避免将历史使用量归零；不主动重放任何工具。

冻结价格放入既有 reservation JSON：价格版本、Provider/Model、输入/输出
每百万 Token 的整数微美元单价和对应 Token 上界。计费向上取整到微美元，
不用浮点数。旧 P4 人工上界保留为 legacy_bound.v1，不伪造为真实单价。
调用原始状态仍为 reserved/succeeded/failed/unknown；pending/settled 是报表
映射而非新的持久状态。所有试验仅用 mock Provider 的合成价格。

全量迁移、20 OS 进程模型/工具竞争、已知失败退款、未知保留、重复结算、
同内容不同任务、事务回滚和账本/聚合守恒必须在真实合成 PG 上检查。
