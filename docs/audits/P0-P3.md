已复现并修复的缺陷：

| 编号 | 影响 | 修复 |
|---|---|---|
| F1 | Go 测试已 PASS 但包尚未结束的截断日志，以及缺少 testcase 的 JUnit，可被验收器标成 PASS | 检查包 start/terminal、重复/乱序结束及测试完成集合；用实际 pytest 阶段/子测试事件核对 JUnit 计数与条目 |
| F2 | RefreshReady 可与尚未提交的撤销 verdict 并行，创建随后即失效的 ready/输入记录 | 依原锁顺序先锁结果，再用新 SQL 语句读取 verdict；返回前再次验证 Orchestrator 租约。Claim 原有复查已阻止实际越权执行，不把该缺陷夸大为已绕过 Worker 授权 |
| F3 | ReadSnapshot 在 guardTask 后等待数据库锁，租约过期仍返回快照，削弱 PrepareContext 最后的授权检查 | 返回前再次用数据库时间核对 Task 租约，过期返回 LEASE_EXPIRED；补充 Ready 无新写入时的过期租约回归 |
| F4 | selected 模式只按总分排序，堆入目标关键词的普通日志可先占预算，导致本可装入的关键证据被拒 | 先按关键证据分组，再按相关性及稳定 ID 排序；预算计算仍以实际 JSON 字节为准 |
| F5 | PublishArtifact 接受包含空格、换行或非 ASCII 的工具版本，后续 BuildSnapshot 却拒绝，产物无法供后继消费 | 发布入口复用同一 ValidVersion 校验，写文件/元数据之前拒绝，Task/预算/事件保持不变 |
| F6 | CAS.New 在检查软链接前 MkdirAll，虽返回拒绝，已在链接目标创建目录 | 用目录描述符逐级 Openat/Mkdirat，所有组件 O_NOFOLLOW；最终核对打开目录 inode，拒绝路径替换 |

每项都有保留的失败复现和修复后检查。数据库竞争用独立 OS 进程、真实 PostgreSQL 锁等待及管道同步，
没有以 sleep 推测竞争顺序；租约实验观察实际数据库时间。合成测试只清理自己创建的 schema/目录。
完整命令、实际退出码、运行产物哈希、源码指纹及最终统计见本轮 accept.json；统计由运行结果生成。
首次全量检查因 pytest 9 的 JUnit 子测试计数行为而失败：成功子测试计入 tests 总数，但没有独立 testcase。
保留该失败，并新增只记录用例身份摘要/阶段/结果的事件采集器，核对所有选中用例的 setup/call/teardown，
单独报告实际成功子测试数；不以忽略计数差异或跳过测试消除失败。该采集器针对锁定的 pytest 9.0.2。

本次改动细化已有约束，没有引入新的持久化协议、状态或迁移，不需要改变冻结契约。
审查没有发现需在 P2 可信离线适配器范围内新增修复的已复现问题；这不代表任意不可信代码可安全在宿主执行。
Go→Python 自动 Worker 派发、租约维护、结果回写的整体闭环仍未接通，需要在后续集成中明确落卡；
独立 Verifier/Gateway/Sandbox 属于 P5，完整端到端场景属于 P7-02。当前 P3 提供显式受信 API，
Python 候选结果不会自动变成 durable 或 verified。真实模型、生产数据、跨主机和断电实验未运行。
