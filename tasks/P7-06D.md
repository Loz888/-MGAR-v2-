# P7-06D · 官方 tokenizer 与可证明输入预算上界

状态以 `TASK_QUEUE.md` 和 `evidence/batches/P7-06D/accept.json` 的实际验收记录为准。
已按用户“先用二美元…自动停止”的回复实施；依赖 P7-06B。
依据：[ADR-0017](../docs/adr/ADR-0017.md)。D 验收通过前，正式 C 保持 BLOCKED。

## 目标和边界

在用户已经批准的 Flash-1017、24×4、整轮 USD 2 范围内，修订输入预留策略，使小请求
可以在有可验证上界的前提下入账。保留逻辑模型 `flash-1017`、官方 API `deepseek-flash`、
现有 assignment/run UUID、每份 20833 微美元、65536 token、1024 输出 token 及原业务
DAG/工具权限。不能增加预算、减少任务、转移份额、默认重试或新增 DDL。

## 交付范围

- 官方 tokenizer 数据的来源、版本和 hash；审核数据格式，禁止加载远程可执行代码。
- 对最终发送的同一份不可变请求计算输入上界，包括聊天包装与特殊 token；说明官方
  服务端可能增加的内容及其上界依据。无法证明则 BLOCKED。
- 配置/报价证据绑定计数方法和 tokenizer hash；旧全模型容量模式继续可用。
- 既有 PG 原子预留/结算和 unknown 保留使用该上界；计数失败、版本不符、超限在发送前拒绝。
- 仅使用 development 数据、独立进程、真实 PG 和本地 HTTP 做离线验证；不先用 live
  结果调参，不消耗正式分配。D 通过后回到已批准的 P7-06C 执行原实验。

预计影响 provider、live preflight、分析器及有限测试/配置，不超过约 8 个生产文件。
如需更大改动、未设计迁移或不同预算方案，应继续拆分/审阅，不猜测实施。

## 必须验证

1. 多字节、特殊标记、空串、最大边界和嵌套 JSON 输入上界可审计，报价取整可重算。
2. 计数器失败/缺数据/hash 错/模型不符/计数不适用时，物理请求数为零。
3. 实际 usage 超出绑定上界时，保留 unknown 原份额、停止整轮，不缩小费用后重试。
4. 真 PG 并发最后份额、跨 Run/Task、真实进程崩溃恢复与报价冻结继续通过。
5. 所有分配身份/模型/工具权限/Verifier 不变；Go/Python 全量回归无失败/跳过/xfail。

验收命令：`go test -count=1 ./internal/provider ./eval/live ./tests/integration`、
`python -m pytest -q tests/unit/test_live_analysis.py`、`bash scripts/test.sh --offline`。
所有命令和测试必须实际记录；未完成计数器和上界证明时不能声明 D 通过。

## 停止条件

记录 `evidence/batches/P7-06D/accept.json` 与真实日志。没有可证明的完整请求上界就不启动
正式生成；不能把 API key 已可用等同于付费执行门禁已通过。

实施采用当前官方两条文本消息参考模板下的 UTF-8 字节上界，验证完整 ByteLevel/BPE
数据和包装分支，而非引入远程 tokenizer 执行代码。额外 API 特性不在证明内并拒绝；
包含逐字节性质、闭合 Schema、真 PG 预留/超限/未知、四组 development 闭环和对账绑定。
详见 ADR-0017 的完整推导。正式生成仍只在 D 通过后进入原 C。
