# P3-04 · 依赖追踪、过期输入与增量复用

> **阶段：P3 — Artifact / Context Engineering**  
> **依赖：P3-03**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

让 Plan 改变时能够知道哪些任务必须重算，而不是全量执行。

## 允许修改的主要文件/模块

`internal/context/lineage.go, internal/planner/invalidate.go, tests/integration/invalidation_test.go`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

消费关系图中保存 Artifact SHA/producer/tool config version；输入更新递归标注新 Plan 下需要重执行的节点；未变化分支合法复用旧 Artifact；历史 Task 终态不可变。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

A09：A→C 改变，仅受影响后继重建；平行 B 的产物复用；历史查询不变。

## 反向验收 / 故障或越界（必须自动化）

不得将旧计划的结果无校验直接注入新计划；失败重算不更改旧 Artifact bytes。

## 本卡验收命令

```bash
go test ./internal/context/... ./internal/planner/... -run "Invalidate|Reuse"
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留
- [ ] Go/Python 已存在的全量回归未退化（无法运行说明原因）
- [ ] 写出 `evidence/batches/P3-04/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
