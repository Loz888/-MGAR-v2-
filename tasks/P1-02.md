# P1-02 · 版本化 DAG 校验与原子 Plan Commit

> **阶段：P1 — 持久化工作流与 DAG**  
> **依赖：P1-01**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

实现图算法和 Plan Version CAS，杜绝环、越界和部分提交。

## 允许修改的主要文件/模块

`internal/dag/, internal/planner/validate.go, internal/store/plan.go, contracts/plan.schema.json`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

固定 MaxNodes=24, MaxDepth=6, MaxFanout=8；验证 role/tool、同一 Run 依赖、拓扑排序；Plan append-only；锁 workflow 与 orchestrator lease；CAS 更新 active version 并同事务插入 outbox。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

D01/D02/D05：正常图成功，环/无效依赖拒绝，双版本竞争只有一个成功；旧历史可查询。

## 反向验收 / 故障或越界（必须自动化）

并发冲突不得生成半成品新 Plan 或重复 Outbox；旧 owner 不能提交 Plan。

## 本卡验收命令

```bash
go test ./internal/dag/... ./internal/planner/... ./tests/integration/... -run "Plan|DAG"
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留
- [ ] Go/Python 已存在的全量回归未退化（无法运行说明原因）
- [ ] 写出 `evidence/batches/P1-02/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
