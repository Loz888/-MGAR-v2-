# P5-01 · 证据契约与独立 Verifier

> **阶段：P5 — Verifier、安全和沙箱**  
> **依赖：P4-05**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

结果必须带独立可检查证据，Verifier 不信 Agent 自述。

## 允许修改的主要文件/模块

`contracts/{evidence,verdict}.schema.json, internal/verifier/, tests/integration/verifier_test.go`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

针对文件/测试/SQL/引用定义 typed Evidence；结构校验、引用哈希、来源关系、版本匹配；输出 Verdict checks 与失败原因；验证结果 append-only。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

S01/S03：伪造成功、缺失引用、旧来源被拒；真实有效证据通过。

## 反向验收 / 故障或越界（必须自动化）

不能用 Reviewer LLM 的 yes/no 代替独立 proof；无验证数据不能将 Workflow 标记 succeeded。

## 本卡验收命令

```bash
go test ./internal/verifier/... ./tests/integration/... -run "Verifier|Evidence"
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留
- [ ] Go/Python 已存在的全量回归未退化（无法运行说明原因）
- [ ] 写出 `evidence/batches/P5-01/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
