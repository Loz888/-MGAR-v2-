# P3-01 · 内容寻址 Artifact Store 与身份

> **阶段：P3 — Artifact / Context Engineering**  
> **依赖：P2-05**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

所有跨 Agent 结果落成不可变、可核验的对象。

## 允许修改的主要文件/模块

`internal/artifact/cas.go, internal/store/artifacts.go, contracts/artifact.schema.json, tests/integration/artifacts_test.go`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

本地专用私有目录 temp/write/fsync/rename + sha256；DB 元数据写入与 Producer/ACL/Schema 绑定；读取重校验；允许同内容存储去重但来源关系不可合并。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

A05/A07：去重且来源可查，重复读取 bytes 相同，篡改/丢失检测安全失败。

## 反向验收 / 故障或越界（必须自动化）

哈希碰撞不宣称数学不可能；路径遍历、软链接逃逸、非当前租约发布全部拒绝。

## 本卡验收命令

```bash
go test ./internal/artifact/... ./tests/integration/... -run "Artifact|CAS"
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留

- [ ] 写出 `evidence/batches/P3-01/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
