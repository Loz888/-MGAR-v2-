# P6-01 · 全局预算账本与原子预留

> **阶段：P6 — 资源成本调度与可观测性**  
> **依赖：P5-05**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

对整个 Workflow 限制模型调用、工具次数、Token/美元估算。

## 允许修改的主要文件/模块

`internal/budget/reservation.go, internal/store/budgets.go, tests/integration/budget_test.go`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

单一 Budget 行的条件更新+事务账本；支持 pending/settled/unknown/failed；模型不同 pricing 版本冻结；预留、消费、退还、未知上界明确；有效并发硬限制。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

O01/O02：20 进程同时预留，余额不为负，不超 quota；每条 ledger 与聚合数守恒。

## 反向验收 / 故障或越界（必须自动化）

未知用量不可填 0，合法相同 prompt 的不同任务调用不因 hash 相同被误去重。

## 本卡验收命令

```bash
go test ./internal/budget/... ./tests/integration/... -run "Budget|Ledger"
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。
