# P8-03 · 面试 Demo 与项目证据包

> **阶段：P8 — 发布审计与求职交付**  
> **依赖：P8-02**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

技术亮点与实测证据一一对应，可高可信展示。

## 允许修改的主要文件/模块

`docs/demo.md, docs/interview-notes.md, docs/experiments.md, README.md, evidence/releases/interview-pack/`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

完整架构图、8 分钟以内正常/拒绝/恢复演示流程、3 类故障时间线、Ablation 表、已知边界、5 个系统面试问答；简历项目亮点填真实数字和测试引用。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

可在干净环境复现示范命令；每句“已实现/已验证”能映射实际代码/测试/evidence。

## 反向验收 / 故障或越界（必须自动化）

不得把计划功能写成已经实现；不可将 Mock 成功率写成真实模型结果。

## 本卡验收命令

```bash
bash scripts/release_gate.sh --verify-evidence && git diff --check
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留
- [ ] Go/Python 已存在的全量回归未退化（无法运行说明原因）
- [ ] 写出 `evidence/batches/P8-03/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
