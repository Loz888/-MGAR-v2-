# P7-03 · 公平单 Agent / 固定 / 动态基线

> **阶段：P7 — 真实业务闭环与严格实验**  
> **依赖：P7-02**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

建立公平对照 runner，不能仅让新方法独享额外预算与工具。

## 允许修改的主要文件/模块

`eval/baselines/, eval/runner.py, eval/config/arms.yaml, tests/unit/test_eval_runner.py`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

实现 B0/B1/B2/B3/B4 和 A1/A2 组；同题同版本工具/预算/独立 oracle；Group 记录配置和 input manifest；每 Run 独立 namespace。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

E04：配置校验，所有分组分别可离线跑且数据隔离；相同 seed 稳定复现 Mock 结果。

## 反向验收 / 故障或越界（必须自动化）

不能让 B0 缺失核心 Tool、改变预算后仍写公平；失败任务不删样本。

## 本卡验收命令

```bash
python -m pytest -q tests/unit/test_eval_runner.py && python eval/runner.py --provider mock --arms B0,B1,B2,B3,B4
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。
