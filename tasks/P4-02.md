# P4-02 · Dynamic Replanner 的有限计划增量修改

> **阶段：P4 — 可靠 Handoff 与局部重规划**  
> **依赖：P4-01**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

模型提出纠错后，系统只激活合法的新 Plan Version。

## 允许修改的主要文件/模块

`internal/planner/replan.go, contracts/replan.schema.json, tests/integration/replan_test.go`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

失败分类触发 replan suggestion；Policy 限制 MaxReplans、depth、cost；base plan CAS；完成节点/Artifact 只合法复用；记录理由与差异 Diff；无法解决诚实终态。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

H06/H08：变化分支重算，不变分支复用；非法图全部拒绝，原计划仍可恢复。

## 反向验收 / 故障或越界（必须自动化）

模型反复建议同一失败计划时有界停止；不能让 LLM 写任意状态转移。

## 本卡验收命令

```bash
go test ./internal/planner/... ./tests/integration/... -run "Replan"
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留
- [ ] Go/Python 已存在的全量回归未退化（无法运行说明原因）
- [ ] 写出 `evidence/batches/P4-02/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
