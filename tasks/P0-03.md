# P0-03 · 严格测试/证据流水线

> **阶段：P0 — 工程脚手架与可复现环境**  
> **依赖：P0-02**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

统一一张卡的 PASS/FAIL/NOT_RUN 规则和证据格式。

## 允许修改的主要文件/模块

`scripts/preflight.sh, scripts/test.sh, scripts/accept.sh, scripts/bootstrap.sh, internal/accept/, evidence/batches/`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

记录命令、退出码、版本、Git SHA 与 Assertion；pytest/go test 静态和动态 Skip 检测；离线 suite 单独执行；JSON 审计字段固定；脚本严禁自动付费。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

空测试明确 0 tests（不称 PASS 功能）；有测试时报告真实数量、输出和 evidence/accept.json；Linux/WSL2 preflight 成功。

## 反向验收 / 故障或越界（必须自动化）

注入测试失败/pytest.skip/t.Skip 都必须使本卡验收失败；Mac/Windows 原生进程注入不得假装通过。

## 本卡验收命令

```bash
bash scripts/preflight.sh && bash scripts/test.sh --offline && bash scripts/accept.sh P0-03
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留
- [ ] Go/Python 已存在的全量回归未退化（无法运行说明原因）
- [ ] 写出 `evidence/batches/P0-03/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
