# P8-02 · 干净环境复现与最终发布门禁

> **阶段：P8 — 发布审计与求职交付**  
> **依赖：P8-01**  
> **执行粒度：仅本卡；完成后停止并交回人工验收**

## 本卡目标

用户不用开发机缓存也能部署和验证；失败必须阻止发布。

## 允许修改的主要文件/模块

`docs/operations.md, docs/architecture.md, README.md, scripts/release_gate.sh, evidence/releases/`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

创建全新 DB 与临时 repo，按 docs/README 安装+迁移+启动+E2E+故障+安全+统计；收集机器环境、Git SHA、所有断言、NOT_RUN 原因；release_gate 输出 PASS/ENGINEERING_ONLY/BLOCKED。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

E08/E09：可从零复现，报告区分离线工程验收/真实模型验收；非法凭据/skip/缺证据阻止 Full Release。

## 反向验收 / 故障或越界（必须自动化）

不能把可选 live NOT_RUN 标为完整 verified；也不得覆盖已有用户本地 DB/目录。

## 本卡验收命令

```bash
bash scripts/release_gate.sh --fresh-sandbox
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。

## 交付清单与停止条件

- [ ] 仅本卡功能完成，相关测试先失败后通过（适用时）
- [ ] 正向/反向断言通过，未通过项原样保留
- [ ] Go/Python 已存在的全量回归未退化（无法运行说明原因）
- [ ] 写出 `evidence/batches/P8-02/accept.json` 和相关日志，注明 commit/未提交状态
- [ ] 在 `TASK_QUEUE.md` 标记真实状态，简述已知边界，向用户交付结果并**停止**

**不得做的事：** 擅自进入下一任务卡；用 Mock 数据伪装真实模型实验；为了 PASS 跳过测试；自行发付费请求；默认执行危险宿主操作。
