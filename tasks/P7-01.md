## 本卡目标

评测数据先于调 Prompt 冻结，防止调数据迎合模型。

## 允许修改的主要文件/模块

`fixtures/, eval/cases/, eval/oracle/, eval/dataset_manifest.json, tests/e2e/fixtures_test.py`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

至少 60 条离线工程 fixture（10 类×6）；真实模型专用冻结 24 条（简单8中8难8；至少6个拒绝负例）；两个业务类别；地面真值独立脚本/静态断言；manifest SHA 固定。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

## 反向验收 / 故障或越界（必须自动化）

模型生成内容不能写入 Ground Truth；跑后改答案必须提升 dataset version。

```bash
python -m pytest -q tests/e2e/fixtures_test.py && python eval/oracle/validate_manifest.py
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。
