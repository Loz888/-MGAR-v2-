## 本卡目标

ActionAgent 根据上游证据提出修改并在临时环境验证，不在用户仓库直接写。

## 允许修改的主要文件/模块

`agentkit/mgar_agents/action/, fixtures/incident/go-repo/, tests/e2e/action_test.py`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

受限 Go 文件范围+补丁大小+文件内容 hash；提交修复建议为 Artifact；本阶段通过最小本地受控 Tool Adapter（白名单命令、无任意 shell）在临时 Worktree 执行 go test，回填真实退出码/证据；**只能执行人工构造且可信的合成 fixture**。完整 Tool Gateway 与不可信代码隔离在 P5-03/P5-04 建立，届时需将此调用路径接入 Gateway/Sandbox 并回归。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

指定 bug 能提出合法 patch 并跑真实 Go 测试；失败 patch 报失败且可反馈下一轮。

## 反向验收 / 故障或越界（必须自动化）

不在白名单文件/源码根目录写，禁止 shell 注入与符号链接逃逸；伪造测试通过要被拒绝。

## 本卡验收命令

```bash
python -m pytest -q tests/e2e/action_test.py
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。
