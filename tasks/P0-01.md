## 本卡目标

建立架构决策、接口目录及术语表，防止不同 Codex 会话互相重写协议。

## 允许修改的主要文件/模块

`docs/architecture.md, docs/adr/ADR-0001.md, docs/protocols.md, contracts/README.md`

如确需新增测试/小型辅助模块，可在本卡范围内增加；若涉及未批准的持久化协议修改或跨阶段大量重构，停止并提交 CHANGE_REQUEST。

## 开发步骤与设计要求

落地 01/02 文档中的实体、状态机、信任边界和 12 项不变量；记录执行适配器可替换策略；明确不复制原 Coding Runtime；标注当前未实现。

必须遵守 `02_ARCHITECTURE_CONTRACTS.md` 对身份、状态、预算和版本的约束；LLM 不能直接更新权威状态，所有新写路径均有真实测试和审计。

## 正向验收（必须自动化）

文档具备版本号、术语定义、状态转移表、单机边界；ADR 给出“本地适配器 vs 原 Runtime 适配器”的权衡。

## 反向验收 / 故障或越界（必须自动化）

不存在把 Mock 表述成真实 Agent 的描述；没有跨主机容错和外部 Exactly-once 承诺。

## 本卡验收命令

```bash
python scripts/validate_plan_docs.py（本卡建立静态检查）；git diff --check
```

命令中的脚本/测试路径属于应交付接口；如仓库尚无该脚本，先在本卡实现所需脚本或等价测试入口并更新说明。Codex 必须记录真实运行的命令及退出码，不得仅复制上述命令假装执行。
